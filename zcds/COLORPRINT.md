# 点色指纹（colorprint）—— 页面身份判定

本页说明 `C:\projects\wxgame\zcds\colorprint.py` 这一层：怎么靠"点几个像素的颜色"确定当前是
哪个页面。逻辑移植自旧项目 `C:\projects\wxgame\mxdzz`（`libs/app.py` 的颜色对比部分 +
`ctrl.py` 的 `link` 状态机），针对本项目做了若干加强，见 §3。

> **边界**：点色指纹**只负责"这是什么页面"**；页面内该点哪里（`Page.act()`）在读得到字时才用 OCR，
> 读不到的（图形按钮、✕ 徽章、价格护栏）用 §12 那六把颜色尺子。两者互不干涉，不要把指纹和动作混在一起改。

> **用户定案（2026-09-03）**：OCR 准确率太低而且速度太慢 —— **识别成功之后，脚本里一律用点色**。
> 真机实测：点色判完全表 **2.2 ms/帧**，全图 OCR **675 ms/帧**。所以 OCR 是"点色一点收据都没有"时的
> 最后兜底，不是常规路径；`test_zero_ocr.py` 把这条钉成回归测试。

## 0. 一句话原理

一帧图像属于某页，当且仅当该页的**若干"十字 5 点判色单元"在当前帧全部命中**
（`is_multi_color`：任一点不中即整条不中）。命中即定页，**不需要 OCR**。
全中落空时还有第 2 级"**软命中**"：只差 1 个点（动画遮挡）且甩开第二名足够多，仍算点色定页、
仍不跑 OCR —— 见 §6.1。OCR 只剩"一点像素收据都没有"时的第 3 级兜底。

一页可以有多组指纹（`prints`），代表同一页面的不同形态（按钮亮/暗、有无红点等），
**任一形态全中即算这一页**。

## 1. 为什么把"猜页面"从 OCR 换到点色

之前每一帧都跑一遍 OCR，靠关键词打分选页，有三个反复出现的毛病：

1. **慢且不稳**。OCR 本身几百毫秒一轮，而且识别结果会漂：同一张图上一轮读成
   「点击继续」、下一轮读成「点击维续」，关键词就匹配不上了；`scale=0.5` 缩放还会丢小字。
2. **弹窗压在大厅上时两页关键词同时命中**，只能靠注册顺序硬压，属于碰运气。
3. **文字是最容易变的东西**（活动文案、倒计时、玩家名、数值），而页面框架像素
   （顶栏图标、按钮描边、标题底纹）几乎不变。

所以：**判页看像素，干活看文字**。像素命中就定页，OCR 只在指纹全部落空时兜底。

## 3. 相对 mxdzz 的六项加强

1. **单点 → 十字 5 点单元**。mxdzz 的 `points` 是散落的单点，一个点撞上纯色背景就命中，
   容易误判。本项目标定单元固定为十字：`OFFSETS = [(0,0), (2,0), (-2,0), (0,2), (0,-2)]`
   （`tools/pick_print.py:35`）。一个单元 = 5 个点，一个指纹 = 3 个单元 = **15 个判色点**。
   想退回 mxdzz 的单点风格：`pick --no-cross`。
2. **随机采样 → 稳定性筛选**。`App.get_points` 是随机取点；这里是先把语料里所有候选点
   跑一遍（`stable_points`），只保留"在本形态的每一帧都命中"的点（`--min-frames 1.0`），
   再贪心地挑"能排除最多数其它页面"的单元（`--min-sep 45` 保证单元分散，不挤在一块同色区域）。
3. **一页一组的 `points` → 一页多组 `prints`**。同页不同形态（`--cluster 4.0` 自动分簇）
   各存一条指纹，任一全中即判为该页。
4. **坐标归一化到基准尺寸**。指纹一律在 `REF_SIZE = (552, 1006)` 下标定（`pick` 阶段
   `im.resize(REF)`）。**匹配时不缩放图像**，而是 `scale_points()` 把坐标按
   `w/552, h/1006` 换算到当前截图尺寸——省一次重采样，也避免插值改色。**但点击坐标不做换算**，见 §4。
5. **`pos_tol` 邻域容差**。mxdzz 只比对该像素的精确位置；本项目在 `(x±pos_tol, y±pos_tol)`
   的方块里任取一像素命中即算命中，用来吸收缩放取整带来的 1 像素偏移。
6. **`print_score()`**。返回 0~1 的命中比例，把"差多少个点"量化出来，标定和排障时能看
   margin（见 §7、§10），不再只能看到"中/不中"。

## 4. 坐标与容差约定（**移植数据前务必读这段**）

- 本项目全库坐标都是 **`(x, y)` = (列, 行)**，在 `REF_SIZE = 552 x 1006` 基准下标定；
  取色是 `arr[y, x]`。
- **⚠ mxdzz 的约定正好相反**：它的 `is_color(x, y, ...)` 内部写的是 `self.capture()[x, y]`
  （`libs/app.py`），numpy 是 `[行, 列]`，所以它 `points[i][0]` 实际是**行号**。
  → **不要把 mxdzz 页面里的 `points` 数值直接搬过来**，那样等于把坐标沿主对角线镜像。
  要移植就重新用 `pick` 标一遍。
- `degree`：**越大越严格**。85 → 每通道 ±19；100 → ±0。`pos_tol`：坐标容差像素，0 = 不允许漂移。
  这两个参数都是 `Page` 的类属性（`degree` / `pos_tol`），**可以按页覆盖**；
  当前全部页面用默认 `degree=85`、`pos_tol=1`。
- 语料图片尺寸可以各不相同，但**长宽比必须和 552x1006 一致**，否则换算后坐标会整体错位。
- **⚠ 只有"判色坐标"会换算，"点击坐标"不会**。`CHEST_SLOTS`、`MASK_POINTS` 和各家 `act()` 里的坐标
  全是 552x1006 下的常量，`App.click()` 只加窗口偏移不缩放。所以**窗口必须钉在 552x1006**：
  `auto_bot.py` 每轮调 `g.set_window_size()` 校正（尺寸已对时只有一次 `GetWindowRect`，开销可忽略），
  不想让它动窗口就加 `--no-resize`（届时指纹层和动作层都可能失效）。

## 5. 标定流程（新页面 / 改版后重标）

1. **拍图**：把某页的重复截图丢进 `C:\projects\wxgame\zcds\shots\`（同一页面至少 2 张，见 §9）。
2. **登记标签**：在 `C:\projects\wxgame\zcds\tools\pick_print.py` 的 `LABELS`（`:37`）里，把图名
   追加到对应 label 的列表中，写作 `'shots/<文件名>'`（不带 `.png`）。**标注必须人工确认**，
   一张图不能同时属于两个 label。
3. **自检**：`python tools\pick_print.py check` 看标签是否齐全、尺寸是否合规格。
4. **选点**（**必须带 `--region 0,130,552,1006`** 把顶栏的账号资源数字排除掉，原因见 §9-6）：

   ```
   python -X utf8 tools\pick_print.py pick --label lobby --region 0,130,552,1006
   ```

   常用参数与默认值：`-n 5`（每形态单元上限）、`--min-cross 3`（至少几个单元）、
   `--step 4`（候选网格步长）、`--margin 8`、`--cluster 4.0`、`--degree 85`、
   `--pos-tol 1`、`--min-sep 45`、`--min-frames 1.0`、`--region x0,y0,x1,y1`、
   `--no-cross`、`--drop-lonely`。
5. **回填**：把 `pick` 打印出来的代码块**原样**贴进 `C:\projects\wxgame\zcds\pages\<label>.py`
   （单形态用 `points = [...]`，多形态用 `prints = (...)`）。**不要手改坐标数值**，
   手改等于作废整个跨帧验证；要调就改参数重跑 `pick`。
6. **验收**（两条都必须 exit 0）：

   ```
   python -X utf8 tools\pick_print.py verify -v
   python -X utf8 test_print_route.py
   ```

> 别名标签：`vip_month` 的形态被并进 `pages\vip_popup.py`（`GROUPS = {'vip_popup': ['vip_popup', 'vip_month']}`，`:61`），**不会新建 `pages\vip_month.py`**。

## 6. 路由规则（`pages/base.py`）

定页面分**四级**，逐级降级；**上一级只要给出结论就绝不花下一级那份 OCR 钱**：

```
route_prints(pages, img, prefer=()) -> (page, score, src)   # 纯点色: 绝对全中 + 锚点全中 + 软命中, 绝不碰 OCR
detect_ocr(pages, f)                 -> (page, score)       # 第 4 级兜底, 只在上一行返回 None 后调用
```

判定顺序，**命中即返回**：

1. **指纹全中（第 1 级）**：`src = 'print-prefer'` / `'print-order'`
   - `prefer` 是上一页声明的 `next_pages`（对应 mxdzz 的 `Ctrl.link`），先只查这些候选页；
   - 没全中的话再按 `ALL_PAGES` 注册顺序查其余页。
2. **锚点相对点色全中（第 2 级）**：`src = 'anchor-prefer'` / `'anchor-order'` —— 见 §6.2。
   专治**会浮动的弹窗面板**：绝对坐标一漂就整片不中，改成"先找锚点，再按固定偏移读点"。
3. **软命中（第 3 级）**：`src = 'print-prefer-soft'` / `'print-order-soft'` —— 见 §6.1。
   点色**没全中但只差 1 个点**，且甩开第二名足够多，仍然算"点色定的页"，**照样不跑 OCR**。
   主循环额外要求**连续 2 帧同一页**才按它动手（`auto_bot.SOFT_ACT_AFTER`），第 1 帧只认页不出手。
4. **全图 OCR 打分（第 4 级）**：`src = 'ocr'` —— 前三级一条收据都没有（新页面/被别的窗口挡住/改版）
   才允许花这份钱，阈值 0.3。**并列最高分时用点色部分命中率拆伙**（`detect_ocr`）：大厅右上角常驻
   "月卡"，和 `vip_popup` 的关键词同样拿 1.0，只按注册顺序会误判成弹窗 —— 真机 2026-09-02 就踩在这上面。
5. **`unknown`** → `src = 'unknown'`。

日志每轮打 `[指纹] <page> <src> <score>`，`<src>` 的取值就是上面这四种来源。

### 6.1 软命中：动画遮住一个点时不许退回 OCR（2026-09-03 落地）

**要修的坑**（真机 01:42 日志）：战斗页满屏都在动，指纹 25 个点里只要有一个被动画遮住就不算"全中"
→ 旧版整轮白退到全图 OCR（675 ms）+ 靠文字猜页。留出集 47 帧真机图上重标后的指纹已经 100% 全中，
但"差 1 点"这种最琐碎的失效在实时画面里必然反复出现，所以补一层软命中，而不是放宽容差。

`pages/base.py` 的三个常量，**三条同时成立**才算软命中（少一条就老实退回第 3 级）：

| 常量 | 值 | 为什么必须有 |
| --- | --- | --- |
| `SOFT_MIN_PTS` | 8 | 否则"1 个点没中"也满足"差 ≤1 点"，`ad_popup`/`claim_popup`/`diamond_popup`/`unknown` 这些**零点数的页**会白捡命中（0/0） |
| `SOFT_MAX_MISS` | 1 | 最多缺 1 个点，按该指纹**自身点数**换算成分数门限（15 点→≥0.933，25 点→≥0.96） |
| `SOFT_MIN_MARGIN` | 0.20 | 必须甩开第二名 0.20 以上 —— 防两张相似页在半途中转帧上互相冒充 |

- 判定函数：`best_print(page, arr)`（最强指纹及其点数）→ `soft_hit(scored)`（挑候选 + 算 margin）
  → `match_print()` 打 `-soft` 后缀 → `is_soft(src)` 给主循环用。
- **参数实验**（`scratch/scripts/soft_tune.py`，222 帧真机+语料）：`exact`（不许软命中）205、
  `m1_02`（差 1 点 + margin 0.20）**205**、`m2_02`（放宽到差 2 点）205 —— 软命中**一个误判都没增加**，
  剩下 17 帧是本来就没指纹的 `other`/`unknown`。所以取最保守的 `SOFT_MAX_MISS=1`。
- **端到端锁死**：`test_print_route.py` 第 [10] 项用假分数钉死 6 条门限，再用真图 + `blotch()` 验证
  "遮 1 点→软命中""遮 2 点→交 OCR"；`test_cpu_offline.py` 场景 [7] 验证主循环"第 1 帧不动作、
  第 2 帧放行、全程零 OCR"；`test_zero_ocr.py` 全语料 + 留出集扫描后断言 OCR 模块压根没被 import。
- **⚠ 造"差 1 点"的用例图时 `blotch` 半径必须是 `r=1`**：指纹是**十字 5 点一组**（中心 + 上下左右 2px），
  涂 7x7 会一次干掉**整个单元**（5 个点），score 直接掉到 0.800 —— 那是"页面真的变了"，不是动画遮挡。

- **`match_print()` 一旦某页全中立刻 `return`**，所以"同一帧两页同时全中"由
  **`prefer` + 注册顺序**裁决。当前注册顺序：

  ```
  ad_popup > claim_popup > chest_info > chest_open > diamond_popup
                 > vip_popup > result > battle > matching > lobby > unknown
  ```

  **弹窗必须排在大厅/战斗之前**：弹窗压住底层页面时，被压页面的框架点仍可能全部命中
  （它的顶栏还在画面外露着），靠顺序才能判成弹窗。
- `src = 'ocr'` 是**"指纹失效"信号**，不是正常路径：偶尔出现是画面剧变（可接受），
  持续出现说明页面改版了，要重新标定（§9）。`src` 带 `-soft` 偶尔出现属正常，**长期**带说明
  指纹标到了动画上，按 §9-2 重标（别靠加大 `SOFT_MAX_MISS` 掩盖）。
- `test_print_route.py` 的第 [3] 项锁死了"**像素与文字矛盾时听指纹**"：故意造一张
  大厅图但 OCR 读到弹窗文案的用例，必须判成 `lobby`。这条测试不许削弱。
  第 [6] 项锁死 §6-3 的同分 tie-break（用缩放过的真机大厅帧复现，含反向用例：只剩弹窗
  文案时不得被抢给大厅）；第 [7] 项是"顶栏闸门"，`lobby` 指纹一旦落回 y<130 直接判失败。

### 6.2 锚点相对点色：面板会浮动时，绝对坐标是假的（2026-09-03 中午落地）

**要修的坑**（真机日志）：`result -> vip_popup` 有概率 `[指纹] vip_popup ocr 1.00` ——
整轮 82 条路由里唯一那条 OCR。原因不是像素变了，而是**那张弹窗面板整体上下浮动**，
`vip_popup` 的绝对点色坐标跟着一起漂，于是"永远差几个点"。

做法：`Page.anchor_prints = [ {anchor: ..., points: [...]}, ... ]` —— 每组的点写成**相对锚点的偏移**。
`match_print()` 在第 1 级（绝对全中）失败后、软命中之前，先 `anchor_fingerprints(page, img)`：

| 环节 | 实现 | 为什么这样定 |
| --- | --- | --- |
| 找锚点 | `find_close_badge(img)`（§12 那把现成的尺子，已改成 PIL / ndarray 都能吃） | 徽章是弹窗自带、**跟着面板一起动**的刚性部件，绝对坐标不可信但相对偏移永远可信 |
| 读点 | `anchor_points(fp, anchor)` 把偏移平移成绝对坐标，再走同一个 `print_score()` | 复用原语，不新写判定逻辑 |
| 门限 | **只允许全中**，且组内点数 `< SOFT_MIN_PTS(8)` 的锚点组一律不许软命中 | 5 个点的组只要放宽容差，`vip_popup` 就会在别的弹窗上白捡命中 |
| 缩放 | 锚点组一律用 `size = REF_SIZE`，**不做 scale** | 面板浮动是平移不是缩放；再叠一层缩放等于把误差平方 |
| 顺序 | 排在绝对全中**之后**、软命中**之前** | 绝对坐标能全中时绝不花那 6ms 找锚点 |

- **代价**：一次锚点查找 6.3 ms（绝对全中 2 ms，全图 OCR 675 ms）。只有前 1 级失败才付。
- **665 帧真机审计**（`scratch/scripts/anchor_audit_0903.py`）：锚点路径**只在 vip_popup 那 1 帧命中**，
  其余 664 帧在所有别的页上得分 **0.00** —— 一个误命中都没有。
- **回归**：`test_anchor_print.py` 5 段（锚点组命中 / 异页 0.00 / 偏移与绝对互不串台 / 6ms 成本 / 真机帧回放）。
- ⚠ 弹窗页现在有两种标法：**面板位置固定**的用普通 `prints`；**会浮动**的用 `anchor_prints`。
  两者可以共存（第 1 级先试绝对，不中再试锚点），所以"加了锚点"不用把原来的绝对指纹删掉。

## 9. 已知风险（别踩）

1. **薄语料的形态没有跨帧验证**。看 §7 的"各形态覆盖帧数"：`matching` 4 帧、`versus` 4 帧是现在最薄的两组
   （`chest_open` 8 帧、`vip_popup` 两形态 4/5 帧次之）。原先"只用一张图标定"的形态
   （`matching` 全部、`result` 第 4 形态、`vip_popup` 的 `vip_month`）已经随真机补帧长到 ≥4 帧，
   但**4 帧仍然是"测过但不厚"**：换赛季 / 换活动皮肤时最先失效的就是这两组。补图优先级 `versus` > `matching`。
2. **指纹刻意不覆盖动画区域**（倒计时数字、随机矿块、飘字、奖励动效）。好处是稳，
   代价是**改版换皮会整页失效**，表现为一直接 `src=ocr`。那是**重标定信号，不是 bug**，
   不要靠放宽容差去掩盖。
3. **`degree=85` / `pos_tol=1` 是在"同源重复截图"上调出来的**。真机走 PrintWindow 抓帧
   可能有色彩管理/DWM 合成带来的色差，届时需要放宽（`degree=80` 或 `pos_tol=2`），
   但**放宽之前先跑 `verify -v` 看 margin**，放宽之后必须再跑一次确认 margin 没有逼近 1.0。
4. **弹窗顺序即正确性**。新增任何弹窗页，必须注册在被压页**之前**（见 §6），否则弹窗
   出现时会被底下的 `lobby`/`battle` 抢走身份。
5. 语料里**混入不同皮肤/不同语言**的截图会直接把标定的点选歪，`pick` 前确认同质。
6. **⚠ 顶栏（y<130）是账号资源数字，不能当指纹依据**。2026-09-02 真机实测：旧 `lobby` 指纹 15 个点
   **全部**落在金币/钻石/兵力数字上，而语料 21 张恰好数值相同 -> `verify` 的 21/21 是**假绿灯**；
   换到真机只剩 11/15（固定缺 4 点，连采 8 帧一模一样），整页路由退化成 `src=ocr`，机器人 20 轮零命中。
   `lobby` 已用 `--region 0,130,552,1006` 重标（25/25 全中 / 异页误中 0 / margin 0.20，覆盖 [25, 19, 4]），
   并由 `test_print_route.py` 第 [7] 项钉死"lobby 指纹不得进 y<130"。
   - **`battle` 已同样解决**（2026-09-03）：旧指纹 15 个点全在 y58~114，语料 13 帧数值恰好相同 ->
     `verify` 的 13/13 也是**假绿灯**。真机补拍 6 帧（`shots/battle_live_004258~004314`）后实测
     旧指纹在真机帧上只中 10/15，日志长期是 `battle ocr 0.90`。用
     `pick --label battle --region 0,130,552,1006 --cluster 40` 重标成 2 形态
     （19/19 全中 / 异页误中 0 / margin 0.27 / 覆盖 13, 6），最小 y=172 已离开顶栏。
7. **弹窗有入场动画，指纹不能标在动画区**（2026-09-03 实测）。`vip_month` 旧形态在补拍的新帧上只中

8. **图形按钮 OCR 读不到，只能按颜色找**（见 §12）。这不算指纹风险，但要知道：定页可以靠像素，

9. **`levelup` / `hero_level` 语料只有 4 / 5 帧，而且全是同一个等级状态**（2026-09-03 早晨新加）。

## 10. 排障

| 症状 | 怎么看 | 怎么办 |
| --- | --- | --- |
| 某页 `verify` 不过 | `verify -v` 看命中比例 | 比例 ≈0.93（14/15 之类）= 差点，通常是被动画或弹窗盖住 → 补拍重标；比例 <0.4 = 整页框架变了或坐标错 → 查截图尺寸/长宽比/是否改版 |
| 日志一直 `print-*-soft` | `missing_points(img, fp)` 点名是哪几个点 | 偶尔一次正常（动画遮挡，见 §6.1）；**同一页长期 soft** = 指纹标到了动画上 → 重标，别去加大 `SOFT_MAX_MISS` |
| 不知道是哪个点漏了 | `colorprint.missing_points(img, fp, degree, pos_tol)` | 返回这帧里没命中的点，按坐标去图上眼看 |
| 一直接 `src=ocr` | 日志里 `[指纹] <page> <src> <score>` | 说明该页所有形态都没全中 → 按 §9-2 重标定，别去动 OCR 关键词 |
| 两页互相抢 | `verify` 的命中矩阵行 | 把冲突页的指纹错开区域重标（加大 `--min-sep`，或用 `--region` 限定） |
| 想救急放宽 | 单页 `degree = 80` 或 `pos_tol = 2` | 只改那一页的类属性，然后**必须**重跑 `verify`，确认 margin 没接近 1.0 |
| 换账号 / 资源一变就整页认不出 | `test_print_route.py` 第 [7] 项会点名指纹落在顶栏的页 | 指纹落在顶栏资源数字上 → 用 `--region 0,130,552,1006` 重标（见 §9-6） |

### 为什么这几条不走 OCR

- **✕ 是图形不是文字**：月卡/VIP 弹窗的关闭键是一个红色圆形徽章，OCR 读不出来。旧代码找不到
  `X`/`关闭` 关键字就退回点遮罩，而遮罩点是固定的 `(270,860)` —— dry-run 8 轮全在重复同一个无效点击，
  弹窗关不掉，挂机原地卡死。改成按颜色找徽章后真机实测：`(455,461)` 一击关闭 → 下一轮 `lobby` 1.00。
  命中点复核：`chest_info` 面板算出 `(468,165)`，和手工标定的 `CLOSE_POS=(470,167)` 只差 2px。
- **侧页根本没有指纹**：任务/商店这类页面没进 `ALL_PAGES`，`route()` 只能给 `unknown 0.00`，
  而 `unknown.act()` 只会瞎点遮罩 → 玩家手动点进任务页，机器人就永久卡在那。
  左下角返回箭头是这类页共同的、纯图形的出口，用颜色认它比给每个侧页标指纹便宜得多。
- **价格判据：颜色是主判据，文字只有否决权**（2026-09-03 凌晨顺序反转）。顶栏那颗紫宝石图标主色约
  `(222,62,246)`，看着很好认，但全语料 89 帧里 **77 帧**都有同色系紫 UI（面板底纹、按钮描边、奖励光效），
  **整帧**按颜色判价会误伤到不能点。能用的尺度只有一个：先用点色把黄按钮外接框找出来
  （`BTN_BOX=(120,730,440,840)` / `0xFDCA33` ≥ 2000px，18 帧实测 npx 7655~8061、中心恒 `(275,795)`），
  再数**按钮内下半那条 40px 带**里的紫宝石像素 —— 免费 13 帧恒 **0** / 付费 5 帧恒 **362**，
  阈值 `GEM_MIN = 60` 隔着整个量程，比任何一次 OCR 都硬（本页 ROI OCR 还要 369ms）。
  旧版"先 OCR 认文字"在真机 00:57 翻过车：价格画成"紫宝石图标 + 裸数字 30"，OCR 只读得到 `30`、没有单位，
  文字判据一条都不命中 -> 机器人真替玩家花掉 30 宝石（顶栏 114->84）。所以 `PRICE_RE` / `PRICE_BARE_RE`
  现在降级为**附加否决**：只有这一帧本来就带文字（同一轮里别的页跑过 OCR）才看，读到价格就拒点。
  判付费后点的是右上角关闭徽章，一次都不碰按钮。39 个用例锁在 `test_price_guard.py`。
- **广告页那三处都是 SDK chrome，不是游戏文字**：同一句「已获得奖励」在不同广告源下药丸右边界是 164 和 209，
  倒计时数字还会掉位（211 -> 204）；广告创意本身每帧都变，OCR 读到的内容根本没有稳定的键可匹配。
  所以 `ad_claim_pos` / `ad_close_pos` / `ad_pill_right` 只量**几何**（色块外接框、白像素最右列），见 §18/§19。
- **价签是数字图形，不是可读文字**：`25` 和 `50` 只差一个 `0`，OCR 在这种 14px 描边字体上会把它们读成同一个词；
  而「这一位有没有闭合孔」是**零容忍度**的精确判据 -> 四档一次都不混，见 §17.2。

> 这些尺子都是 numpy 级别的像素判据（15~20ms），比再跑一次 OCR 便宜，也不受缩放影响。
> 新增同类判据时请像 `find_close_badge` 一样：**先把阈值和实测分布写进注释**，再跑一遍全语料确认 0 误报。
## 13. 动作层也改成点色：`result` / `chest_open` / `lobby` / `chest_info` / `levelup` / `hero_level` 全轮零 OCR（2026-09-03 落地，凌晨补 `chest_info`，早晨补 `levelup` + `hero_level`）

§12 那六把尺子是「点色做判据的特例」，这一节是**整页动作层都不再读字**。凌晨补的 `chest_info` 是最后一块拼图：它以前是**所有有指纹的页里唯一还留着 ROI OCR 的**（价格护栏），现在价格改看带内宝石像素；只剩没指纹的 `ad_popup` / `claim_popup` 两页的动作层还会去读字。

## 14. 点色优先的四道闸门 + 一张跨页拉黑表（2026-09-03 凌晨落地）

「点色优先」不等于「点色失败就立刻回去跑 OCR」。真机跑起来之后，OCR 是被**四道闸门**一层层挡掉的，
下表顺序就是 `App.step()` 里的代码顺序：

| 闸门 | 常量 / 函数 | 触发条件 | 拦下之后 | 实测代价 |
| --- | --- | --- | --- | --- |
| ① 软命中稳帧 | `SOFT_ACT_AFTER = 2`（`auto_bot.py`） | 指纹只差 ≤1 点（动画盖住一个点） | 页面身份认下，但**这一帧不动手也不跑 OCR**；连续 2 帧同页才按稳定帧放行 | 0 ms |
| ② 转场闸门 | `is_transition(img)`（`pages/base.py`） | 全表零收据，且是白烟（近白 ≥ `TRANS_WHITE_MIN=9`% / 饱和度 ≤ `45` / 亮度 ≥ `120`）或黑屏（亮度 ≤ `BLANK_LUM_MAX=25` / 饱和度 ≤ `25`） | **整帧跳过，什么都不点** | ~2 ms（一次 numpy 全帧扫描） |
| ③ 零命中先等一帧 | `NO_HIT_OCR_AFTER = 2`（`auto_bot.py`） | 全表零收据、又判成不是转场 | 第 1 帧不动作也不跑 OCR；**连着第 2 帧**才允许兜底 | 0 ms |

只有真页面才会连着两帧都不中，那时兜底才是对的。
②③ 合起来之后，留出集 203 帧里原本只剩 3 帧需要兜底（2 张白烟 + 1 张爆炸帧），
而这 3 帧如今分别被 ② 和 ③ 挡住 -> **真机 120 步全程零 OCR**（完整链路见 `README.md`）。
回归锁在 `test_cpu_offline.py` 场景 [6]（两帧：帧 1 `page is None` 且未跑 OCR，帧 2 才 `unknown` + 一次 OCR）

## 15. 单元级标定法：当两页长得只差 10px（2026-09-03 早晨，`hero_level` 实战）

`pick_print.py pick` 报的 margin 是**点级**的：每个判色点单独拿去和异页语料比，撞中就算一分。
两页只要共用一整块同款配色（`hero_level` / `chest_info` / `matching` 是同一条蓝横幅 + 白字标题），
单点的"独占性"看着都还行，但**整体平移 ~10px 之后彼此仍然很像** —— 实测直接选点最好也只有
margin 0.28~0.50，而且它挑不出"这 5 个点其实是同一根横幅上连续 5 个像素"这种**假独立**。

于是这一页换成**十字单元**这个粒度（一个单元 = 中心 + 上下左右 4 点，正好是 `pick_print._units` 的形状）：

1. `scratch/scripts/pick_hero_units2.py x0,y0,x1,y1 [step] [label] [sep] [maxworst]`
   —— 逐单元算两个数：① 这个单元的 5 个点在 **188 张异页语料**上是否**整单元零命中**；
   ② 它在异页上的**点级重叠**最大值（`maxworst` 卡阈值）。两条同时满足才进候选池。
2. `scratch/scripts/compose_hero.py "x,y x,y ..."` —— 按选中的单元中心（同一套 `OFFSETS`）从第一张
   本页语料取色拼出整组 `points`，**立刻**全语料复核「本页全中 / 异页误中 / margin」，并打印可直接
   粘贴的 `points = [...]`。换别的页标定时改脚本里那行 `label` 就行。
3. `scratch/scripts/chk_print_any.py <label> <ptsfile>` —— 第三道眼：给定 `points` 文件，逐帧命中情况
   加「异页最高分是哪一张、差几个点」，用来人工判断这个 margin 低得有没有道理。

本页结果：8 单元 / 40 点，5/5 全中、异页误中 0、margin **0.100**。
纯横幅版能刷到 0.000，但 8 个单元全是底色、语义上一个都不认识 —— **刻意留了 2 个字形单元**
（"英雄""等级"白字笔画）当锚点，宁可 margin 差一点：将来若改版，横幅色还在、字形先变，
先掉的是 `hero_level` 的判定而不是"把别的页认成本页"，报错方向是"认不出这页"(会存
`shots_live/stuck_*.png` 取证)而不是"认成别的页去点按钮"，这个方向是安全的。

> 配套的现场取证工具：`scratch/scripts/tap_shot.py X Y OUTPNG [delay]` = 点一下 -> 抓一帧 -> 打印路由，
> `X=-1` 只抓不点。`hero_level` 的入口（主页左上角那个等级六边形 `(30,113)`）就是拿它一格一格试出来的，
> 也是它当场证明新指纹在真机帧上是 `hero_level print-order 1.000` 而不是 `chest_info ocr 1.20`。


## 16. 侧页逃逸：先认「栏」，不认「页」（2026-09-03 上午落地）

大厅下面那排 5 个页签（商店 / 卡牌 / 战斗 / 城堡 / 排行）以前是**黑洞**：脚本一旦点进去就"不认识自己"，
而 `unknown` 只会试青色返回箭头 —— **这些页根本没有返回箭头**，于是烧 OCR、判 `unknown`、原地打转。
新手引导把整屏压暗时是同一个症状（指纹是明屏标死的，压暗后整片失效）。

本轮把这两类合并成一条原则：**认不出页没关系，先认「底部那排页签在不在」、再认「亮的是哪一个」**。
两个判据都是纯点色，`nav_hits()` 单帧 ~0.1 ms，比一次全图 OCR（675 ms）便宜四个数量级。

### 16.1 「栏在不在」：16 个跨 5 页完全一致的静态像素

`NAV_POINTS` 由 `scratch/scripts/probe_nav.py` 扫 y905..996 整条带得出：只保留在**五个页签的所有真机帧上
逐通道极差 <= 6** 的像素（白色图标描边、深色描边，不随页签内容变），16 个。
`NAV_DEGREE = 92` 即每通道 **±10**（`tolerance(92)`，比页面指纹默认 85→±19 更严）下 `nav_hits(img) >= NAV_MIN_HIT = 12` 即判"栏在"。

**门限是量出来的，不是拍的**（`scratch/scripts/probe_navcorpus.py` 跑 `shots/` + `shots_live/` 全部 802 张）：

| 分组 | 张数 | `nav_hits` 极值 | 结论 |
| --- | --- | --- | --- |
| 带导航栏 | 152 | **最低 14** | 门限 12 不会漏 |
| 不带导航栏 | 650 | **最高 9** | 门限 12 不会误 |

不带栏那 650 张里最高的 9 张全是**压暗的引导帧**（亮度整体掉一档、命中跟着掉），
所以另留一个 `NAV_SOFT_HIT = 9` 当"栏可能在"的软水位 —— **软命中只许用于观察，绝不允许据此点页签**
（同 §6.1 的软命中哲学：宁可这一帧不动，也别按错）。`NAV_BAND = (905, 996)` 把统计窗口钉死在页签带内，
防顶栏/棋盘里的青色混进来。

### 16.3 新页 `tab_other`：故意不标指纹

兄弟页签是同一套壳换内容，给"商店页"标指纹等于给活动美术挖坑。所以 `pages/tab_other.py` 明确

**按上下文点名**（为此新增 `App.page_by_name(name)`）：

```
点色零命中 -> guide_targets() 认引导 / nav_present() 且 nav_tab_cx() != 276
            -> page, score, src = page_by_name('tab_other'), 1.0, 'escape-tab'
            -> 落到 step() 尾巴 -> act() 点 (276, 950)，类级 GAP = 2.5 s 节流
```

- **注册顺序**：`versus` 之后、`unknown` 之前。主循环拿 `self.pages[-1]` 当兜底页，插错会把 `unknown` 挤出去。
- **判据顺序**：导航栏必须排在 `back_arrow_pos()` **之前**（见上表卡牌行），否则先走箭头逃逸就原地打转。
- `test_print_route.py` 的"无指纹页"检查放行 `CONTEXT_PAGES = ('tab_other',)`，避免下次有人以为漏标。

### 16.4 🔴 在 `step()` 里加出口，绝不能提前 `return`

`App.step()` 的结构是「一路判到得出 `page`，**函数尾巴**统一 `page.act(self)` -> 记日志 -> 返回」。
2b2 两条逃逸出口最初写成 `return self.pages[-1], 0.0, False` ——
于是 **`act()` 一帧都没执行**，日志却写着"交 unknown 处理"，表现出来就是"一直在处理、手没出去"的死循环，
而日志看上去完全正常，最难查的那种。

正确写法：出口分支只**赋值** `page, score, src`，然后落到尾巴。附带两个坑：

1. `self._nohit_streak` 要停在 `NO_HIT_OCR_AFTER - 1`（清 0 会退化成"每隔一帧才肯动一次手"）；
2. 提前分支要补 `ocr_ran = False`，否则尾巴取不到局部变量 -> `UnboundLocalError`。

`test_side_page_escape.py` 的 [1]/[2]/[4] 三个场景都是**桩掉 `click` 记录落点、断言真的点出去了**，
专门用来抓"只 return 不 act"这一类写法。

### 16.5 新手引导模态：1.8 ms 认压暗层 + 手型，指尖 = 掌心 + (-37, -24)

引导帧的指纹整片失效（压暗），但不需要 OCR 也认得出：遮罩层 + 那只跳动的**手型指引**是纯色形状。
`guide_targets(img)` 用颜色阈值 + 连通域找手型，返回"该点哪几处"（指尖），
`unknown._candidates()` 拿到后逐个点，**认引导一律不花 OCR**。

- 指尖坐标 = 掌心中心 + **`(-37, -24)`**（真机核对：点掌心会点到遮罩外，点指尖才是引导要的地方）。
- 曾用 `cv2.connectedComponents` 做整层形状分析：**3.4 s/帧**，直接弃用；现在这版 **1.8 ms/帧**。
- 与 `nav_present()` 冲突时**引导优先**（引导帧也可能露出页签带），所以 2b2 里先算 `guide`，
  `on_tab = not guide and nav_present(...) and nav_tab_cx(...) != 276`。

## 17. 战斗格子读价签：「50 优先」以前为什么从未生效（2026-09-03 午后重写）

用户报的现象只有一句：**「战斗中只会开 25 的，开完就不开了」**。两句都成立，而且是两个独立的坑，
都发生在**动作层**（页面早就靠点色认对了，是「该点哪一格」判错）。

### 17.1 为什么以前分不出 25 / 50

旧 `_classify_word` 把整块价格字缩到 30x18，和 `battle_templates.npz` 里的 `t25` / `t50` 做**归一化相关**，
阈值 `0.32` / `0.04` —— 松到什么程度：真机日志里绝大多数格子既不像 25 也不像 50，全落进"分不清"的
`2d` 桶，于是 `rank_cell()` 写没写"50 优先"都一样（旧桶序是 `矿 > 50 > 2d > 25`，而 `2d` 装下了整张棋盘）
-> **实际退化成只按 y 点，最下面那排 25 先被点光，点完就没有下一档可点，看起来像"停手"**。
`battle_templates.npz` 从此没有任何代码引用（README 文件地图里已标注可删）。

### 17.2 新判据：位数 + 各位闭合孔数

这个字体里**只有 `0` 带一个闭合孔**，`1` / `2` / `5` 都没有 -> "几位 + 每位几个孔"就把四个价签钉死：

| 签名 | 价 | 说明 |
| --- | --- | --- |
| `(0, 0)` | 25 | 两位都无孔 |
| `(0, 1)` | 50 | 末位是 `0` |
| `(0, 1, 1)` | 100 | 三位，后两位是 `0` |
| `(0, 0, 1)` | 250 | 三位，`2`/`5` 无孔、末位 `0` |
| 其它三位数 | `cls=3` | 认不出，排在最后（兜底档） |
| 不是价格块 | 丢弃 | 见下面的头盔幽灵格 |

`_price_class()` 的三步：先在**行轮廓**上取"最宽的那条横带"（价格数字自成一带，上方问号的白点被切掉），
再按**列轮廓**切成单字（`_runs`），最后逐位数孔（`_digit_holes`）。实测 318 帧 1488 个白色标签，
四簇 614/535/205/65，**零混叠**，裁图肉眼逐张核对过。

### 17.3 四个必须记住的坑

1. 🔴 `cv2.connectedComponents(inv, connectivity=4)` **必须写关键字**：位置参数写 `4` 会被当成
   `labels` 吞掉，实际仍按 8 邻域跑 -> 1px 笔画的字四角"漏气"，背景全连通，**孔数恒为 0**，
   四个档全部判成"认不出"。这个 bug 只在离线回归里才看得见，因为真机上它表现为"不动手"而不是报错。
2. **贴右边缘被裁的价签**：截图右侧有黑边，末位数字常被切一半 -> 孔数不可信。
   传 `clipped=True`，改用 `_left_edge_gap()`（数字块左起 2 列填充行号的最大断档）分 `0`（连续）/`5`（断 2 行）。
   日志里的 `clip=True` 就是这条路径，战斗语料里不少见。
3. **兵营的白色头盔图标 = 幽灵格**：它的宽高恰好落在旧的 `is_tag` 区间里，旧版把它当成价格标签
   （实测 105 个，签名都是"1 段"）-> 同一个六边形格被"图标"和"价格"各算一次，点它等于白点一次。
   现在只允许**命中签名表**的块留下，头盔自然被丢掉。
4. **`cls=3` 里有一个不是格子的东西**：左下角那颗"镜头复位"按钮也被读成三位数价格。
   判据保留（它确实长得像），但 `act()` 里**永不点它**，`test_price_class.py` 专门锁死这一条。

### 17.4 档位与冷却（`pages/battle.py`）

```python
CELL_COOLDOWN = 2.5    # 旧值 5s = battle 页 poll 3.0s 下每两轮才出手一次
CELL_RETRY    = 25.0   # 点过的格子拉黑这么久, 到期回头允许再点(升级/新格)

rank_cell(c) -> (tier, -near_tower, -c['y'])   # 50矿 > 50兵营 > 50问号 > 25 > 100 > 250 > 认不出
```

`tier` 里 50 档再按 `icon` 分 `ore(0)` / `barracks(1)` / 其它(2)；同档内先点靠塔那一侧（兵线来的方向），
再按行从下往上。更要紧的是 **`act()` 改成遍历候选、点第一个没被拉黑的**：
旧版只看 `clickable[0]`，第一名一旦在冷却里就整轮 `return False` ->
真机 12:11:07~12:12:42 **连续 95 秒一次没点**，当时棋盘上还有 14 个白格。
日志新增 `跳过已点N格` / `解禁N格` 两条可观测线索。

回归：`test_price_class.py`（逐帧读数，含被裁帧与镜头复位）+ `test_battle_rank.py`
（同一帧只点最高档 / 按 50矿>50兵营>25 连点 / 三格全拉黑那一轮不动手 / `CELL_RETRY` 到期解禁后再点回高档）。
真机 13:07 段实证档位生效：`点格子 (473,668) ore cls=50 clip=False 解禁2格` 抢在同类 `unknown cls=25` 前面。

## 19. 看广告自动领奖：点黄色[领取] -> 自动看完 -> 自动关（2026-09-03 午后）

用户诉求：**「这个界面上点击黄色的看广告领取，可以看广告的地方就自动看完」**。
链路全部零 OCR（`config.WATCH_ADS = True` 是唯一开关，关掉就退回"不点[领取]、只点[继续]"）。

### 19.1 三把新尺子（现在是"三把 + 一把门闩"，见 19.3）

| 尺子 | 干什么 | 关键分界 |
| --- | --- | --- |
| `ad_claim_pos()` | 结算页横幅右侧那颗黄色[领取] | 同一个黄 `0xFDCA33` 在[立即开箱]上也有 -> 用**外接框形状**分开：领取是扁宽胶囊（实测 w 124~126 / h 32~38），开箱被面板挤成窄高块（w 58 / h 63，左边缘还被取样框切在 x=300） |
| `ad_close_pos()` | 广告页右上[关闭] | 见 §18 |
| `ad_pill_right()` | 广告页左上状态药丸右边界 = "放完了没有"（**尺子一**，现在是 `ad_pill_state()` 的薄包装） | 见 19.3 |
| `ad_pill_state()` | 同一颗药丸一次量**三个读数** `(右边界, 带内白像素, 左边界)` | 右边界 = 尺子一、白像素 = 尺子二、左边界 = **顶栏门闩**；见 19.3 |

全语料复扫（815 帧 552x1006，`scratch/scripts/adclaim_scan2_0903.py`，11.5s）：
`ad_claim_pos` 命中 **46 帧，全部是 result 页**（含 17 张 `LABELS=result` 标定帧），中心恒 `(412,781)~(412,782)`，
其余 769 帧 **0 误命中**；`ad_close_pos` 命中 8 帧全是广告页，0 误命中。
结算页 22 张语料里 17 张带横幅（点[领取]）/ 4 张无横幅（直接点[继续]）/ 1 张广告盖脸（两处都 None）。

### 19.2 为什么要专门的"看广告窗口"（`auto_bot.py`）

广告**创意每帧都变**，点色定不了页；中途误点会让奖励作废。所以窗口一旦 arm，
`step()` 顶部（414~423 行）就**优先于路由**：不定页、不跑 OCR、不点任何别的东西，
只由 `_ad_tick(img)` 管这一件事。它返回四个状态：

| 返回 | `step()` 行为 |
| --- | --- |
| `'wait'` | 直接 `return`（不定页、零 OCR） |
| `'acted'` | 本轮点了[关闭]，直接 `return` |
| `'done'` | 确认已离开广告页 -> 清窗口，**同一帧**掉回正常路由（不用白等一轮） |
| `'giveup'` | 超时无奈 / 压根没进广告 -> 同上撒手 |

六个时间常量（都在 `auto_bot.py` 147~242 行）：
`AD_WATCH_MIN = 12.0`（这之前绝不动手）、~~`AD_WATCH_MAX = 40.0`（等满就认定放完）~~
**（2026-09-05 用户定案「广告得看满时间, 不能中途退出」-> 该常量已删, 时间不再是放完证据, 见 §35.7）**、
`AD_WATCH_TOTAL = 100.0`（一条广告最多占用主循环这么久，防死等）、
`AD_CLOSE_RETRY = 3.0`（点过[关闭]还赖着就每 3s 补一次）、`AD_CLOSE_CONFIRM = 12.0`（关闭动作最多盯这么久）、
`AD_NOT_AD_AT = 4.0`（等 4s 仍是"游戏自己的页"且始终没广告顶栏 -> 判定没在看广告，`giveup`，别把主循环锁死）。
"游戏自己的页"用 `_ad_page_hard()`：点色**硬命中**（非软命中）某个已知页，2ms，不花 OCR。

### 19.3 判"放完了"：只能用**本场相对缩窄**

同一颗药丸两种文案（实拍 2026-09-02 12:47 连拍 5 帧）：
`广告 | 27 秒后可获得奖励` -> 右边界 **211**，`广告 | 8 秒后...` -> **204**（数字掉一位边框跟着缩），
`广告 | 已获得奖励` -> **164**。而**另一路广告**（`shots/ad_popup_live122400`）同一句"已获得奖励"的右边界是 **209**。
真机 13:08 又量到一场 **270 -> 209**：倒计时态和放奖态差 61px，但绝对值完全换了一个区间。
-> 绝对阈值必翻车，所以记下**本场见过的最大宽度**，缩掉 `AD_PILL_SHRINK = 28` 才算放完。
注意 `ad_pill_right()` 在**正常页也会返回 176~329**（顶栏任何白字都算），
所以它**只在 `ad_close_pos()` 命中时才调用**，绝不单独当判据。

#### 19.3.1 第二把尺子：带内白像素总数（量"有几个字"，与边框位置无关）

右边界只量"最右那根竖线在哪"。万一某家 SDK 把"倒计时"和"已获得奖励"渲染成**同一个宽度**，
尺子一永远不响，只能干等 `AD_WATCH_MAX = 40s`。所以同一帧再数一次带内白像素总数 ——
字数少了像素就少，是同一件事的第二种量法。`ad_pill_state()` 一次把三个读数都量出来。

同一场广告连拍 5 帧 + 两个反例（`scratch/scripts/pill_scan_0903.py`，单位 px）：

| 帧 | 右边界 | 带内白像素 | 左边界 | 说明 |
| --- | --- | --- | --- | --- |
| `watch_124711` | 211 | 827 | 32 | 倒计时 27s |
| `watch_124723` | 211 | **830** | 32 | 本场峰值（基准就记在这一帧） |
| `watch_124735` | 204 | 794 | 32 | 倒计时掉到 8s：右边界只缩 **7px**(<28)、白像素只少 **4.3%**(<15%) -> 两把尺子都不许响 |
| `watch_124746` | **164** | **606** | 32 | `已获得奖励`：右边界缩 **47px**(>=28) -> **尺子一先响**，白像素同时少 27.0% |
| `watch_124758` | 164 | 606 | 32 | 放奖态稳定 |
| `ad_popup_live122400`（**另一路 SDK**） | 209 | **914** | 39 | 同一句"已获得奖励"，白像素比上面那场的**倒计时**还多 |
| `watch_124707`（**广告画面糊上顶栏**） | 257 | 157 | **222** | `ad_close_pos()` 这一帧返回 **None**，两把尺子必须一起作废 |

- 尺子二阈值：`AD_PILL_SHRINK_PCT = 0.15` **且**连续 `AD_PILL_LOW_HOLD = 4.0s` 都少才算。
  倒数第二行那 914 就是"不许定绝对阈值"的实证 —— 和尺子一款子一样，只能跟**本场峰值**比。
- 真机全天 7 场广告 **7/7 都是尺子一先响**（`药丸缩窄 270->209`），尺子二触发 **0 次**：
  它是**保险，不是替代**。回归 `test_ad_watch.py` 的 [3b] 子用例专门伪造"右边界全程不缩、只有白像素变少"
  的序列，逼尺子二独自收手一次。

#### 19.3.2 顶栏门闩：左边界漂移 = 这一帧的读数不可信

`watch_124707` 那帧广告创意糊到了顶栏上：白像素从 830 暴跌到 **157**、左边界从 32 跳到 **222**，
但广告**根本没放完**。没有门闩的话尺子二会判成"字变少了 = 已获得奖励"-> **提前点[关闭] = 奖励作废**。
所以 `_ad_tick()` 记下药丸**左边界基准**（跟"白像素最多"那一帧一起记），
漂移超过 `AD_PILL_LEFT_TOL` 就把**这一帧两把尺子的读数全部作废**（也不清基准，下一帧继续量）。

## 20. 第 4 条零 OCR 出口 = 弹窗关闭徽章（2026-09-03 午后落地）

### 20.0 为什么还要第 4 条出口

前三条出口（§16.2 / §16.4 / §18）认的都是**游戏自己的页面**：新手引导模态、底部兄弟页签、侧页青色返回箭头。
剩下这一类不一样 —— **一个模态弹窗压在某个游戏页上面**：

- 它把底下的导航栏一起盖住了 → 页签出口不响（`nav_present` 要看到 16 个静态像素）；
- 它没有左下角的青色箭头 → 箭头出口不响；
- 它没有大白气泡 + 手套 → 引导出口不响。

旧版这种帧的完整遭遇：点色全表不中 → 白烧一次 **675ms 全图 OCR** → OCR 也认不出页名（弹窗内容随账号进度变，本来就没法标指纹）→
落到 `unknown` → 只能按 `MASK_POINTS` **盲点遮罩**，而模态弹窗压根不吃遮罩点击 → 原地死循环。

新出口的道理和 §16.4 一样：**这帧的身份判据本身就是那个红底白叉 ✕**（§12 的 `find_close_badge`，
`vip_popup`/`chest_info` 早就在用它当关闭键）。认出它 = 同时知道「这是什么」和「该点哪」，一个字都不用读。

### 20.1 判据链顺序：引导 → 徽章 → 页签 → 箭头（`auto_bot.py` step() 的 2b2 段）

```python
guide = guide_targets(img)
badge = None if guide else find_close_badge(img)
on_tab = (not guide and badge is None and nav_present(img)
          and nav_tab_cx(img) != NAV_LOBBY_TAB[0])
arrow = None if (guide or on_tab or badge is not None) else back_arrow_pos(img)
```

三条排序理由，全是实测出来的：

| 关系 | 为什么 |
| --- | --- |
| 徽章在**引导之后** | 引导那条判据更完整：`guide_targets()` 返回的落点表第 1 个点往往就是同一个关叉，让信息量大的先拿分 |
| 徽章在**页签之前** | 弹窗是模态的，压住的那层导航栏点了也没用；而 `nav_present` 在弹窗半透明遮罩下仍可能误亮 |
| 页签在**箭头之前** | §16.4 的真机教训：卡牌页左下那颗青色卡牌图标会被 `back_arrow_pos` 误认成返回箭头 (84,960) —— 那正是页签自己，点它原地打转 |

和 §16.4 同一条铁律：**认出出口绝不提前 `return`**。只做三件事 ——
`self._nohit_streak = NO_HIT_OCR_AFTER - 1`（停在"已升级"水位，下一帧还零命中就继续出手，不必再白等一帧）、
`ocr_ran = False`、把 `self.f` 换成空 OCR 结果继续走正常动作层。
徽章这一路 `page = self.pages[-1]`（就是 `unknown`）、`src = 'escape-badge'`，日志刷
`[侧页] 点色零命中但认出弹窗关闭徽章 (471, 224) -> 交 unknown, 不花 OCR`。

| 改动 | 为什么 |
| --- | --- |

## 22. 战斗档位盘点写进日志 + 广告额度定案（真机第 20 轮，2026-09-03 17:17:26 → 17:38:01）

### 22.1 为什么要往点格子日志里加一盘"档位清点"

用户 2026-09-03 中午的原话：**「现在战斗中只会开 25 的，开完就不开了。应该要先开 50 的矿，然后开 50 的兵营，
然后再考虑开 25 的。如果都没有就开 100 的」**。`rank_cell()` 中午已经按这条改过，但**旧日志答不上诉求本身**：
一行 `[战斗] 点格子 (x,y) ore cls=50` 只报**点中的那一格**，事后没法回答
「点 25 的时候棋盘上到底还有没有没点过的 50」—— 只有「跳过已点 N 格」这种间接计数，
而 N 既可能是冷却里的高优格、也可能是同档的旧格，分不开。

现在 `pages/battle.py: tier_census()` 把整盘一次算清，拼在每一行点格子日志的尾巴上：

| 字段 | 口径 |
| --- | --- |
| `在架N` | 本帧 `scan_battle_cells()` 出的全部白色价签格 |
| `可点M` | 再扣掉冷却表里还没到期的 key（`cell_key()` = 标签中心按 16px 取整） |
| `红K` | 本帧红色价签的个数 = **看得见但钱不够**的格子（2026-09-04 第 38 轮补，见 §34.7 ⑤） |
| `50矿:1 50兵:2 25:1` | 只对**还能点**的格子按 `rank_cell()[0]` 分档计数，计数为 0 的档不写 |

两个刻意的设计，读日志时别搞反：

- **盘点在写冷却表之前算** → `可点` 含本帧正要点的这一格。所以 `可点1 25:1` 的意思是"棋盘上只剩这一格能点"，
  不是"还有一格没点"。
- `cell_key()` 是从 `act()` 里抽出来共用的，盘点和冷却表用同一个 key，不会再出现两处 16px 取整口径漂移。
- **`在架` 掉了先去看 `红`**：`在架` 低 + `红` 高 = 扫描器看得见整盘、只是买不起（正常）；
  `在架` 低 + `红` 也低 = 判据瞎了（§34 那个 bug 的形状就是白+红一起归零）。第 38 轮之前没有这一列，
  两种情况在日志里长得一模一样，定位花了两小时。

## 23. 大厅宝箱五态码表：红角标 = 此刻能白嫖（2026-09-03 晚，真机第 21 轮）

用户诉求：**「这里宝箱下面有点击解锁，你就点宝箱」**。旧版其实**看到**白字[点击解锁]就点了，
但真机第 20 轮连开 12 次面板、12 次全被判成付费（`带内宝石像素 366`）、12 次拉黑，**一次都没解锁成功**。
原因不在"没点"，而在"点了不该点的格子" —— 卡片底部那几个白字**其实是两种动作**。

### 23.1 四张卡片、五种状态（`LobbyPage.chest_states()`）

| 码 | 卡片长什么样 | 点它会发生什么 | 点不点 |
| --- | --- | --- | --- |
| `o` | 整块纯金按钮 [开启] | 直接开箱，**免费** | ✅ |
| `U` | 深色底白字 [点击解锁] **+ 右上角红角标** | 免费放一个宝箱并起 50 分钟倒计时 | ✅ |
| `p` | 深色底白字 [点击解锁] **无红角标** | 面板只有 [开启 💎120]，**要紫宝石** | ❌ 付费护栏 |
| `a` | 金按钮左边贴了张蓝票券 [[AD]加速] | 看一条激励视频 | ❌（点它 = 看广告，且实测会把窗口抓成黑屏） |

旧版只有 `u` 一档（"按钮行白字 >= 120"），把 `U` 和 `p` 混为一谈 —— 两种卡片的宝箱贴图、白字、
"50分/1时"时长角标**逐像素相同**，白字尺子天生分不开。

### 23.2 唯一区别 = 卡片右上角那颗红色八边形感叹号

肉眼对比（`scratch/chest_probe/cards_row.png`，6 张卡片并排）确认：`p` 与 `U` **只差右上角的 ❗**
（`o` 也带 ❗ —— 语义是"**此刻能免费操作这一格**"，而不是"这格能解锁"，这个语义决定了 `a`/`.` 恒 0）。

- 取样框：`CHEST_BADGE_OFF = (34, 730, 58, 756)` 相对槽中心 x。实测徽章占 `x=中心+36..+52` / `y735..748`，约 16x14。
- 颜色：主色 **`0xFF3B3B`**，`color_pixels()` 数像素。
- 阈值：`CHEST_BADGE_MIN = 60`。

🔴 **必须 `degree=60`，不能沿用默认 90**：`colorprint.tolerance(deg)=int((256-256*deg//100)//2)`，
`tolerance(60)=51` 才罩得住徽章的抗锯齿边；实测同一格 `degree=90` 只数到 **48~55**（< 60 会全判成付费），
`degree=60` 数到 **120~128**。这是一个"容差窄到把自己判死"的典型坑。

第 21 轮内部也有同一件事：19:33:36 `o`(220) 带角标 127，点开之后 19:33:45 那一格就是 `.` 了。

### 29.1 `result` 页聚光灯光晕血案：为什么这条指纹必须有两形态

- **现象**：09-04 01:45 之后，结算页每一帧都只中 **2/25** 点，整条路由退化成全项目**唯一**一条
  OCR 路（每帧多花 ~700ms，还每帧存一张待标语料）。
- **根因**：结算页背景不是静态图，而是"大厅王座厅 + 一束聚光灯"，光强在几十秒里从
  **整屏发白**走到**角落近黑**。实测同一个像素 `#412734 -> #0E1025`，逐通道差 **51/23/15**，
  而 `degree=85` 只容 `tolerance(85)=±19` ⇒ 光晕半径以内的点**天生不可用**，跟 §24 那颗动画精灵
  是同一类错误（那次是"角色会换"，这次是"灯会呼吸"）。
- **修法**：形态 A（25 点，失败页 × 聚光灯亮相位，语料 23/35 帧全中）**保留**，新增
  形态 B（30 点，全部落在**光晕半径之外的画面四角**，语料 **35/35 帧全中**，胜/败 × 亮/暗通吃）。
  `prints` 是"任一形态**全中**即判页"，所以 A 只是历史兼容，真正兜住这页的是 B。
- 语料口径：`LABELS['result']` 现在 35 帧（23 老 + 12 张 09-04 凌晨真机 `_live*`）。

### 29.2 为什么在 `pick` 之外还要一个 `stable` 模式（`tools/pick_print.py`）

`pick` 的做法是：先按像素差把同页帧**分形态**，再在每个形态里挑"最亮最扎眼"的单元。
这正好把 29.1 那种坑放大 —— **"这一批帧里恰好一致"的像素（聚光灯、白字、奖励图标、数字）**
会被优先选中，形态数越多越像"标得很准"，真机上换一批帧就整片失效（result 曾被自动标成 19 形态）。

`stable` 反过来问一个问题：**有没有一组单元，本页所有帧全中、其他页一张都不误中？**

- 只筛满足该条件的单元，**形态数固定 1**；
- 判色基准取**跨帧中点**而不是第一帧（第一帧可能正是这批帧里最偏的一端 —— 实测拿第一帧当基准时
  `chest_open` 的 30 点换到中点基准只中 5 点）；
- `--min-chroma 30~40` 把 `#FFFFFF` 白字/灰描边这类**无色像素**挡在门外（不加就会选出 3 个白字单元，
  正是 29.1 那种会腐烂的点）；
- 🔴 **它报"一个都没有"时不许硬凑** —— 那是在说"这页不能用绝对坐标定页"，该换判据（相对几何 / 出口链）。

### 29.3 一个 Python 作用域坑：复核永远 5/30

`stable` 的复核行原来写成：

```python
xy = [(x, y) for x, _y, _c in fp]      # 🔴 y 不是解包出来的 _y
```

外层 `for k in sel:` 循环残留的 `y` 会被推导式拿走 ⇒ 30 个点全被压到**最后一行的同一个 y** 上判色，
只有最后一个单元能中，看起来像"选出来的单元其实不稳"（实测 `chest_open` 一直卡 5/30，差点据此否掉
一组本来 31/31 全中的好指纹）。现在写成 `xy = [(px, py) for px, py, _c in fp]` 并留了注释。
**通用教训**：复核/量尺的代码出问题时，先怀疑尺子，再怀疑被量的东西。

### 29.4 `--with-dbg` 留出集 + `dbg_*_unknown_*` 不能当负样本

- `shots_live/dbg_NNN_<page>_<hhmmss>.png` 是真机主循环每轮留下的帧，**不参与标定**
  （`pick`/`verify` 都不认它们）⇒ 天然的**留出集**。`stable --with-dbg` 把同标签的留出帧拉进
  "必须全中"，别的标签拉进负样本。
- 战果：`chest_open` 第一版第 6 个单元 **(268,388)** 在 3 张留出帧上整组不中（17/20），
  换成 **(264,332)** 后 31 帧全中 ⇒ **只用标定语料会过拟合，留出集才算数**。
- 🔴 但 `dbg_*_unknown_*` 两边都不算：`dbg` 的标签来自**当时的路由**，而 `unknown` 恰恰意味着
  "当时没认出来"。实证：`dbg_003_unknown_073932.png` 与 `shots/levelup_live073932.png`
  逐像素相同（`maxdiff 0`）—— 它就是 `levelup` 页。拿它当异页负样本会造出**假矛盾**，
  逼着 `stable` 报"这页不能靠绝对坐标定页"。

### 30.8 【结案】"bot 进程里屏幕通道整帧全黑"根因 = **窗口站点访问掩码**（R36 矩阵实测）

R35 那批 `ads_*.png` 全是 1693 字节的纯黑图，而**同一个时刻**独立进程抓同一块屏幕 `mean≈146`。
一开始怀疑"广告层是独立表面、连屏幕 DC 也抓不到"，用 `scratch\tmp\_desk*.py` 单进程矩阵一测，
结论完全不同——**变量只有一个：`OpenWindowStationW` 的访问掩码**：

| 操作 | `capture_screen` mean | PrintWindow |
|---|---|---|
| 不切桌面 | 187~192 OK | OK |
| 只 `SetThreadDesktop(0x10a)` | 142 OK | OK |
| `SetProcessWindowStation(OpenWindowStationW("WinSta0", False, 0x0001))` | **0.0 全黑** | OK |
| station 掩码 `0x037F`(WINSTA_ALL_ACCESS) + 任意桌面掩码 | 142~146 OK | OK |
| station `0x100 / 0x101 / 0x141 / 0x10f / 0x0002` | **0.0 全黑** | OK |

⇒ 旧代码为了"省权限"只申请 `WINSTA_READATTRIBUTES(0x0001)`，站点句柄拿到了，但**本进程的屏幕 DC 被废**：
`GetDC(0)` + `BitBlt` 出来整帧 0 像素，而 `PrintWindow` / `EnumWindows` / `PostMessage` 全都照常，
所以症状是"只有第二通道瞎"。更阴的是坏状态下 `GetDeviceCaps(HORZRES)` 仍返回 1920 —— **不能拿它自检**。

修法（`game_utils.py`）：
- `enter_default_desktop(force=False)` 重写：① 默认先 `desktop_is_interactive()` 自查
  （`EnumWindows` 数带标题的可见顶层窗口），**已经在交互桌面就直接跳过**，不再无脑切；
  ② 必须切时站点掩码用 `WINSTA_ALL_ACCESS = 0x037F`，拿不到才降级 `0x0001`；
  ③ 返回 `(是否切换, 说明)`，旧调用点都是裸调用忽略返回值 ⇒ 兼容。
- `auto_bot.ensure_window()` 末尾加 `_screen_selftest()`：窗口内取 3 点 80x80、
  `im.convert("L").resize((1,1))` 求最大灰度均值（不依赖 numpy），全黑则 `ad_screen=False` 并打
  `[自检] 屏幕通道 ...`。运行时实测 `(False, "已在交互桌面 -> 不切(...)")` + `screen mean 186.3`。

**顺带结掉 R35 悬案**：遮挡探针 `scratch\scripts\ad_cover_probe.py`（PID 20116，04:38:11 起 1500s）
每 0.4s 采样，全程 `covered=False`、`pw_nonblack≈96.5%`、`screen_mean 59~201`（从不 <25）。
所以"点了[领取]没进广告"里那两类（3s 跳大厅 / 停在 result 干等 25~28s）**都不是黑屏广告**，
是真没填充 ⇒ 广告判据继续走 PrintWindow，不需要改用屏幕通道。

### 30.9 广告窗口 0.5s 密拍 + [领取] 免费重试（R36）

### 30.12 语料污染结案：同一秒两张状态码不同的大厅帧 = **两个 bot 并发**（已加互斥量）

`test_chest_unlock` 第 [3] 段突然报一条反例：

|---|---|
| 1 | 按秒聚合大厅帧，**同一秒出现 ≥2 种状态码**的秒记为"歧义秒"，整秒不参与配对 |
| 2 | 面板帧找到的最近大厅帧若落在歧义秒 ⇒ **直接跳过这对**，不退而求其次去配更早的帧 |
| 3 | 打印 `n_amb` / `n_amb_skip` 让人看见被丢了多少 |

`runall` **16 项全绿**。⇒ 绝不用"挑一张状态码自洽的帧"来让测试变绿，那是作弊。

**根因防呆**：`auto_bot.acquire_single_instance()` 用命名互斥量 `Local\ZCDS_AutoBot`
（`CreateMutexW` + `GetLastError()==183 ERROR_ALREADY_EXISTS`）拒绝第二个实例。
坑记录：① 必须 `ctypes.WinDLL('kernel32', use_last_error=True)` + `ctypes.get_last_error()`，
用 `windll.kernel32.GetLastError()` 会被 ctypes 自己的调用抢掉，实测恒为 0；
② 错误码是 **183** 不是 185；③ 句柄要存进模块级 `_MUTEX` 活到进程结束，否则垃圾回收就松手了。
`--dry-run` 与 `--allow-multi` 跳过这道闸；拿不到互斥量（非 Windows / 权限受限）一律放行，
不把正常启动拦死。

### 32.5 闸门跟着改口径：「慢一次」和「点错页」不再同罪（新增 `known_blind.py`）

压暗帧进了留出语料之后，两道老闸门**同时报红**（`test_zero_ocr` 的"需要 OCR 兜底 = 0"、
`test_popup_escape` [5] 的"还要花 OCR 的帧 <= 3"）。这红报得没错——它确实花了一次 OCR ——
但如果只是把上界从 3 抬到 5，**每跑一次真机就得手动抬一次**，闸门会贬值成"永远在调上限"。
所以改成按**失败性质**放行：

| 失败模式 | 后果 | 新口径 |
|---|---|---|
| 点色把一帧**认成另一页** | 会点错按钮（§31 事故形态） | **零容忍**，一次都不许有 |
| 点色**谁都没认领** | 只是那一轮慢 675ms + 动画放完自愈 | 允许，但必须交出一条**独立证据**，且总数有上界 |

`known_blind.unclaimed_note(path, score, src)` 四条**全满足**才放行：

1. `src is None` 且全表最高分 `< SOFT_MIN_MARGIN(0.20)` —— 有页贴着软命中门限来抢，一律不放过；
2. 文件名是 bot 自己存的证据帧：`dbg_NNN_<页>_<hhmmss>.png` / `ocr_<页>_<hhmmss>.png`；
3. `<页>` 在指纹表里 —— **新页面的标签只会是 `unknown`，过不了这条**（§31 那类"没标指纹的新页"照旧报红）；
4. **同一秒（±2s）存在另一族的同名证据帧，且两张图逐字节相同（md5 相等）** ——
   这张凭证的含义是"真机当场用**全图 OCR 复核回了同一页**"：页面身份没错，只是掏了一次 OCR 的钱。
   时间差太远 / 两张图不一样 = 凭证不成立 → 不放行。

- **为什么不用"亮度差"当判据**（我先写的第一版，已废）：battle 标定语料的整帧均值本身就是
  **128.6 ~ 160.7 的双峰**（ legit 波动 32 灰阶），而压暗帧是 137.2 ——
  "比该页语料均值暗 ≥20" 判不出来（battle 语料均值 153.6，只暗 16.4），
  "比语料最暗的那帧还暗" 更过不了（128.6 < 137.2）。
  ⇒ **压暗这件事在整帧均值上不可测，只有"OCR 复核回同一页"是可用的独立证据。**
- **记账而不是免单**：`test_zero_ocr` 现在多打一行
  `其中 §32 设计内压暗盲区: 1 张(上界 12, 占有指纹帧 0.040%)` 并逐张列出理由；
  张数超过 `blind_cap()`（= 有指纹帧数 × 0.5%，下限 4）仍然判红 —— 再多就不叫偶发全屏动画了。
  实测 `battle 1970/1971 → 1971/1971 + 盲区 1`，`需要 OCR 兜底的指纹页帧` 那一行仍然如实显示 1。
- `test_popup_escape` [5] 的上界**保持 3 不动**：3354 张帧里还是只剩 3 张
  （`ck_a2` / `gs_00` / `ocr_battle_051920`，后两张是**没有配对凭证**的老帧，照旧记账），
  压暗帧那两张不再把它往上顶。
- **护栏的护栏**：`test_dim_frame.py` 加第 **[5]** 段，用合成帧反向测分类器自己 ——
  同秒+同页+逐字节相同才放行 / 差 11 秒不放行 / 页名不在指纹表不放行 / 两张图不一样不放行 /
  有页认领不放行 / 分数贴到 0.20 不放行，外加"真机那张压暗帧必须认账、它 9 秒前的正常帧不许被豁免"

### 35.7 「广告得看满时间, 不能中途退出」(用户定案 2026-09-05 17:5x)

`_ad_tick` 原来有一处**按时间提前收手**: `waited >= AD_WATCH_MAX(40s)` 即使药丸没缩窄也点[关闭]
(§19 当年给"不缩窄的 SDK"留的兜底)。用户口径: 时间不是放完的证据 —— 提前点 = 打断广告 + 奖励作废。
改后规则一句话: **[关闭]只认药丸缩窄实证(两把尺子任一), 没有任何时间兜底会替你点它**。
- 拿不到证据 -> 等满 `AD_WATCH_TOTAL=100s` -> `giveup` 撒手 = **一个键都不点**交回主循环;
  广告若还在放, 黑屏帧走 §18 重新 arm 继续等(宁可慢, 不可打断)。
- `AD_WATCH_MAX` 常量删除; `AD_WATCH_MIN=12s` 保留(那是"太早动手"的下界, 不是收手依据)。
- 撒手/重试[领取]那两条 25s 路径不受影响 —— 它们的前置是"通道分歧度证明屏幕上没有广告在放",
  真广告在放时分歧度 ~95% 会先短路成继续等(§30.9), 本来就点不到广告界面上。
- 回归锁: `test_ad_watch.py` 旧断言"等满 AD_WATCH_MAX 还不收手(acted)"**翻转**为三段
  "8s wait / 48s wait / 88s wait + 全程零点击"; 总闸 giveup(不点击)与缩窄->acted 两段原样通过。
- 真机背书: R44~R46 十六条成功链全部是"缩窄"先响(30~36s), 40s 时间兜底历史上**一次都没真用过**
  (§19.4 审计原文: "等满 40s 的 7 次 grep 全是假命中, 真兜底次数 0") —— 删掉零损失。
